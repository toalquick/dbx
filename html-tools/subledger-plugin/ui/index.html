Subledger Finder

Trace customer or supplier entries through reference numbers and balance history identity IDs. Keep the earliest history row (lowest UID), remove later loaded rows, and restore balances from that first row.

Scope

Connections stay within the selected client and customers/suppliers. * selects all entries for that scope.

Data source

Right-click a database or table and choose the “Troubleshoot subledgers” action. DBX asks for read access on first use.

Export complete data for the selected scope. Headers are case-insensitive; comma, semicolon and tab delimiters are supported. Identifiers and decimal amounts retain their original precision.

Snapshot and restore both tables

PostgreSQL: save a complete database copy of both tables, across all clients, before correcting data. This preserves every column, not just the fields used in analysis. Snapshots are independent of the customer/supplier scope above.

Set the connection, database and schema above. Prepare the SQL here, then copy it into DBX’s SQL editor and execute the entire statement. Preparing or saving a plan does not create a snapshot. A successful snapshot creates three persistent backup tables in that schema.

Restore replaces all rows in both tables with the snapshot, including removal of rows added afterward. It keeps the original tables, verifies the restored rows, and rolls back on failure. Foreign keys and triggers remain enabled; external references can prevent restore. This is a row-data recovery tool, not a database backup or schema/sequence rollback. Snapshot tables reside in the same database: retain your normal database backups.
